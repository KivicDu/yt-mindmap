# ADR 0011 — Learning workflow: trash, tags, versions and bilingual captions

## Status
Accepted (Phase 8)

## Context
By the end of Phase 7 the product could build, save and share a mind map. What
it could not do was support everyday study over many lectures:

1. Deleting a project was immediate and permanent. A misclick lost the map,
   notes and transcript with no way back.
2. Projects had no grouping beyond drafts, and the only search looked at titles
   and video ids, not at what the learner had written or heard.
3. An AI merge could derail a good map, and the previous state was gone.
4. Long lectures had no table of contents; learners scrubbed the video by hand.
5. Captions could only be shown in one language, so a Vietnamese learner
   watching an English lecture had to choose between the two.
6. Loading, saving and deleting were silent, and the workspace could not be
   driven from the keyboard.

ADR 0010 rejected a soft delete for accounts. That decision stands: account
deletion remains immediate and permanent. This ADR covers **projects**, where a
short recovery window is expected and cheap.

## Decision

### Trash with a 30-day window
`projects.deleted_at` turns `DELETE /api/projects/{id}` into a soft delete:

- deleting also sets `visibility = "private"` and clears `share_slug`, so a
  link cannot be used while the project sits in the trash;
- restoring clears `deleted_at` but **does not** bring the old share link back;
  sharing must be enabled again deliberately;
- expired rows are purged lazily when the trash is read (`purge_expired`), so no
  scheduler is required;
- permanent deletion stays available from the trash (`purge`), and the endpoint
  refuses to purge a project that is not already trashed;
- the dashboard offers an undo toast right after a delete, in addition to the
  trash section.

Every project query filters `deleted_at IS NULL`; the trash list is the only
place that looks at trashed rows.

### Tags
Tags live in `projects.tags` as a JSON list of short, normalized strings:
lowercase, diacritics stripped, at most 8 per project. Filtering uses a portable
text match (`cast(tags, Text) ILIKE '%"tag"%'`) rather than a second table, which
keeps the schema and the API small. A tag summary endpoint powers the filter
chips. If tags ever need counts across millions of rows or shared vocabularies,
a join table is the next step.

### Content search
`projects.search_text` is a denormalized, diacritic-folded copy of the title,
node labels, notes, summary and transcript. Search is a single `ILIKE` over that
column, so "dao ham" finds "đạo hàm" without a full-text extension.

- The column is rebuilt on every write (`build_search_text`).
- Rows created before the migration are backfilled lazily when they are listed or
  searched, so the migration does not scan every project.
- Results carry the matching snippet and, for transcript hits, the timestamp.

### Version history
`project_versions` stores map snapshots (`nodes`, `summary_so_far`,
`consumed_until`, `title`, author).

- A snapshot is taken **before** an autosave overwrites the map and before an AI
  merge changes it.
- Snapshots are throttled to one per 45 seconds unless forced, and skipped when
  the nodes are byte-identical to the latest one. At most 50 are kept per
  project.
- Restoring first snapshots the current state, then writes the chosen version
  back. The replaced map therefore remains recoverable.
- The API broadcasts the restored tree over the session SSE channel, so every
  open tab converges instead of showing a stale map.
- Restoring also rebuilds `search_text` and resets `last_opened_at`.

### Chapters
Chapters are derived, not stored: top-level nodes with a timestamp become
chapters in playback order, each ending where the next begins. Fewer than two
timed topics means no rail, because a single chapter is not a timeline. The rail
shows the current chapter and seeks on click.

### Bilingual captions
`GET /transcript/track` fetches one caption track for a video without touching
the live session. The transcript panel can show a second track under the primary
line, matched by start time. Translation is not generated by AI: the second
track is whatever YouTube already offers. The session, the map and the AI
pointer keep using the language the learner picked.

### Feedback and accessibility
- A toast stack announces saves, deletes and failures, with an undo action where
  one exists; lists show skeletons while loading.
- Workspace shortcuts: `K` play/pause, `J`/`L` seek, `S`/`T`/`H` tabs, `F` fit,
  `?` help, `Esc` close. They ignore typing targets and modifier combos.
- A skip link reaches `#workspace-main`; detail tabs use roving tabindex,
  arrow/Home/End navigation and `aria-controls`; the shortcut sheet is a
  focus-trapped dialog. Lighthouse accessibility scores 1.0 on the workspace.

## Consequences
- Deleted projects occupy storage for up to 30 days, and their rows remain
  visible to the owner in the trash. Account deletion still hard-deletes
  everything, including trashed projects.
- Tag filtering is a string match over the JSON text. The pattern includes the
  surrounding quotes, so `giai` matches the tag `giai` but not a longer tag such
  as `giai tich`.
- Search depends on `search_text` being kept in sync. Any new field that should
  be searchable must be added to `build_search_text`.
- Version snapshots duplicate node trees. Fifty snapshots of a large map is the
  deliberate upper bound; the oldest are pruned on write.
- Chapters are only as good as the AI's top-level topics and timestamps.
- Bilingual mode needs a second caption track; videos with one track show a
  clear message instead of a machine translation.

## Alternatives considered
- **Hard delete with an undo buffer in memory** — rejected: it loses data on a
  restart and cannot support a trash view.
- **A `tags` table with a many-to-many join** — deferred: more schema, more
  queries, no user-visible gain at this scale.
- **Postgres full-text search (`tsvector`)** — rejected for now: Vietnamese
  tokenization needs an extension or a custom dictionary, and the folded
  `search_text` already covers substring search with the same UX.
- **Storing a diff per version** — rejected: node trees are small, and full
  snapshots make restore trivial and auditable.
- **AI translation for bilingual mode** — rejected: cost, latency and the risk
  of confidently wrong translations in study material.
- **A separate chapters table** — rejected: chapters are a view of the map, so
  storing them would create a second source of truth.
