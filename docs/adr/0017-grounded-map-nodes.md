# ADR 0017 — Ground every map node in the transcript before showing it

## Status

Accepted 2026-11-26 — backend shipped in PR #43.

## Context

The learner asked for a guarantee that the mind map matches the video, without
having to open each node and compare it with the captions by hand. The map is
generated by a model from short transcript chunks; the prompt asks for a
timestamp, but nothing currently *checks* that the label at that timestamp is
actually supported by the words spoken there.

A model cannot guarantee truth, and asking a second model "is this correct?"
just moves the trust problem. What **can** be checked by a machine is whether a
label has a source in the caption stream, and whether a claimed quote really
occurs in that stream. That is the standard this ADR adopts.

Rejected alternatives:

- A "verify" button or per-node manual approval — that is the manual checking
  the learner explicitly does not want.
- Percentages, confidence scores, streak/badge gamification — rejected earlier
  in ADR 0014; this ADR reports only counts a learner can audit.
- Fetching captions or calling AI during search (ADR 0016) — unrelated; search
  badges stay preflight-only.

## Decision

Every node produced by `POST /update-map` passes four stages before it is
merged, cached and pushed over SSE.

### 1. Deterministic grounding

`app/services/map_verifier.py` selects up to three caption cues within 45
seconds of the node's `time` (a cue without `duration`, as produced by ASR,
borrows the next cue's start). The label is scored with the existing
`review.answer_score(caption, label)`, which measures how much of the short
label is contained in the caption. The score is not shown to the learner; only
the pass/fail threshold (0.34) is used internally.

A node that passes keeps a max-two-item `evidence` list of `{start, text}`
cues. Evidence lives inside the node JSON, so no database migration is needed
and version snapshots include it automatically.

### 2. One model repair call

Nodes that fail stage 1 are sent in **one** bounded Gemini call
(`ai_engine.verify_nodes`, max 24 items). The model may only:

- rewrite the label using the quoted captions, **and**
- return a short verbatim `quote` from those captions, or
- set `drop: true`.

It never sees the whole map again and cannot invent a timestamp. The prompt is
built in `ai_engine.build_verify_prompt`; the reply is parsed defensively and
an unusable reply drops the disputed nodes rather than trusting them.

### 3. Deterministic re-check

The model's `quote` must appear in the same captions (normalized substring or
a 0.55 overlap score). This works even when the map language differs from the
caption language: a translated label cannot be compared by word overlap, but
the verbatim quote can. A node whose quote fails this check — or that the model
dropped — is removed together with its descendants.

If the model is not configured, or the daily AI budget is exhausted, stages 2
and 3 are skipped and stage 1 alone decides: unsupported nodes are dropped.
The map never falls back to showing unverified labels.

### 4. Consistent output

`markdown_diff` is regenerated from the verified tree, so the Markdown the UI
sees can never still contain a node the verifier dropped. The response and the
SSE event carry a `verification` object with integer counts only:

```json
{"checked": 6, "grounded": 4, "repaired": 1, "dropped": 1, "model_used": true}
```

No percentage, no confidence number, no "approved" badge.

### Quota and limits

The middleware already charges one AI unit when `/update-map` arrives. A second
unit is charged explicitly by `charge_extra_ai_unit()` when the model repair
stage is enabled, so the daily quota cannot be bypassed by packing two model
calls into one HTTP request. When that extra charge is denied, the route
degrades to deterministic-only instead of making an unmetered call.

`MAP_GROUNDING_ENABLED` and `MAP_VERIFY_MODEL_ENABLED` both default to `true`.
Tests disable them globally and re-enable them only with fake captions and a
fake verifier reply; no test reaches a provider.

### Later map operations

`/output-language` translates labels in place, so evidence survives as-is.
`/session/{id}/restructure` rebuilds the tree from existing content;
`carry_evidence()` copies evidence onto nodes with the same timestamp, without
another model call.

## Consequences

- A generated node either has caption evidence or does not exist. The learner
  no longer has to check each node manually.
- One extra bounded Gemini call is made only when at least one node failed
  deterministic grounding. A fully grounded chunk costs the same as before.
- The evidence is stored but not yet rendered in the UI. Showing it in the
  detail panel (hidden for self-check masked nodes) is a follow-up, not a
  prerequisite for correctness.
- Evidence is derived from captions, not learner notes, so it is safe in the
  shared per-video cache; `strip_private_fields()` still removes only the
  learner-private fields.
- Counters and caches remain in-memory; multi-worker deployment still needs
  the Redis work recorded as the standing P0 gap.

## Tests

`tests/test_map_verifier.py` covers cue selection, deterministic grounding and
evidence, repair from a verbatim quote, hallucinated-quote rejection (including
child nodes), model-less fallback, evidence carry-over, normalizer whitelists,
payload validation, and an end-to-end `/update-map` run asserting both the
corrected diff and the two charged quota units.
